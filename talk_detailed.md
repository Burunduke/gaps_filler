# `gaps_filler` — технический конспект для выступления

> Для аудитории: специалисты по геоинформатике / ДЗЗ.
> Автор: junior Python-разработчик. Цель — рассказать, **что** и **на чём научно** построено в проекте.

---

## 0. Что это вообще такое

`gaps_filler` — плагин QGIS 3 (Processing-провайдер `gapsfiller`), который превращает сырьё с гиперспектральной камеры на борту БПЛА в одну заполненную ортомозаику и оценивает её качество.

**Задача в одном предложении:** взять серию узких полос-«кадров» pushbroom-съёмки, склеить их в единый растр в географических координатах и закрыть пропуски (дыры между пролётами, выпавшие пиксели) научно обоснованной интерполяцией, не нарушая спектральную целостность.

**Окружение:**
- работает как плагин в QGIS Processing Toolbox → шесть отдельных алгоритмов (можно собирать в Model Builder);
- ядро — чистый Python в каталоге [`src/`](src/__init__.py:1), без зависимости от Qt;
- обёртки над QGIS (`*_algorithm.py`) — на корне репозитория.

**Ключевой принцип проекта (важно проговорить вслух):**
> Корректность пиксельных значений важнее визуальной красоты. Видимые швы между кадрами — допустимая цена сохранения исходных спектров. Любое сглаживание / гистограммное выравнивание / фезеринг — только как явная экспериментальная опция, не по умолчанию.

Это и есть отличие от типичных «фотореалистичных» SfM-пайплайнов (ODM, MicMac): здесь спектр пикселя — это измерение, а не картинка.

## 1. Pipeline в целом

```
сырой .bil-куб + .lcf + .times
        │
        ▼
[Этап 0] airborne_georef  — геопривязка одного полёта (raw → GeoTIFF)
        │
        ▼  (повторяется по N пролётам)
[Этап 1] frame_filter     — выкидываем заведомо плохие кадры
        │
        ▼
[Этап 2] mosaic           — склеиваем кадры в единую мозаику
        │
        ▼
[Этап 3] fill_nodata      — заполняем дыры
        │
        ▼
[Этап 4] mosaic_quality   — численная оценка качества vs эталон
```

В QGIS каждому этапу соответствует отдельный `QgsProcessingAlgorithm`; есть и сквозной end-to-end (`HyperspectralPipelineAlgorithm`), который дёргает этапы 1→2→3.

## 2. Чтение входных данных

### Что это за данные
- **`.bil`** — сырой гиперспектральный куб формата ENVI BIL (Band Interleaved by Line). Гиперспектральные камеры дают ~200 спектральных каналов в диапазоне ~400–1000 нм.
- **`.bil.hdr`** — текстовый ENVI-заголовок: размеры, dtype, длины волн, FWHM, порядок интерливинга.
- **`.lcf`** — телеметрия GPS/IMU полёта (формат гиперспектральной камеры): время, roll/pitch/yaw (радианы), долгота/широта (градусы), высота (м).
- **`.times`** — массив временных меток на каждую строку куба (line-time stamps).

### Как читаем
- ENVI-заголовок: тонкая обёртка [`src/envi_io.py`](src/envi_io.py:1) над `spectral.io.envi.read_envi_header` из библиотеки [`spectral`](spectral/) (де-факто стандарт чтения ENVI в Python).
- Сам куб: `rasterio` (ENVI-драйвер GDAL).
- LCF/times — кастомные парсеры в [`src/airborne_georef.py`](src/airborne_georef.py:1).

### Подводный камень для выступления
- `.lcf` и `.times` имеют **разные абсолютные эпохи времени**. В коде они выравниваются по **относительному** времени: из каждого файла вычитается его первая метка. Это типовой грабли «два прибора пишут UTC по-разному».

## 3. Этап 0 — Airborne georeferencing (raw pushbroom → GeoTIFF)

Файл: [`src/airborne_georef.py`](src/airborne_georef.py:1).

### Что делает
Превращает один сырой `.bil` пролёт в георефенцированный GeoTIFF: для каждого пикселя сырого куба вычисляет, **в какой точке земли он был снят**, и пересэмплирует куб в географическую сетку.

### Вход / выход
- Вход: `.bil` + `.bil.hdr` + `.lcf` + `.times`, опционально DEM (TIFF), значение FOV объектива (градусы), высота земли `ground_alt`.
- Выход: GeoTIFF с CRS (по умолчанию EPSG:4326), N бэндов, плюс опционально `<output>.footprint.geojson` — полигон отпечатка пролёта.

### Научная база (главное!)

#### 3.1 Pushbroom-геометрия
Гиперспектральные камеры — **pushbroom-сканеры**: за один тик матрицы снимается одна строка поперёк направления полёта (cross-track), а движение БПЛА «протягивает» эти строки по along-track. Каждая строка имеет свой собственный набор поз (положение + ориентация) — в отличие от framing-камеры, где у всего кадра одна поза. Это базовая модель в учебниках по аэросъёмке (Lillesand, Kiefer; Schowengerdt).

#### 3.2 Интерполяция поз на каждую строку
- `.lcf` даёт IMU/GPS-измерения с ~частотой устройства, `.times` — момент захвата каждой строки.
- В коде: `np.unwrap(yaw)` (чтобы сшить переходы через ±π) → линейная интерполяция всех 6 параметров (lon, lat, alt, roll, pitch, yaw) по времени строки (`np.interp`).
- Это стандартный подход в direct georeferencing для pushbroom-систем (см. Habib, Schenk; ASPRS Manual of Photogrammetry).

#### 3.3 Луч на пиксель (collinearity equations, упрощённая форма)

Для каждой колонки sample строится вектор взгляда в **связанной системе координат (body frame)** аппарата:

```
angle_s = (s − s_principal) / (N − 1) · FOV
ray_body = [0, sin(angle_s), −cos(angle_s)]
```

Затем поворачивается в локальную ENU (East-North-Up) систему через матрицу

```
R_enu_from_body = Rz(yaw) · Ry(pitch) · Rx(roll)
```

(порядок Z-Y-X, тот же, что Tait-Bryan углы в аэро-приложениях). При наличии boresight-калибровки (несоосность IMU и оптической оси камеры) добавляется фиксированный пред-поворот `R_imu_from_camera`.

#### 3.4 Пересечение луча с землёй
Два режима:
- **flat-earth:** плоскость `z = ground_alt`. Аналитическое пересечение, `t = (z₀ − ground_alt) / dz`. Подходит для коротких пролётов над равниной.
- **DEM-aware** ([`dem_ground_grid()`](src/airborne_georef.py:541)): итеративная схема — стартуем с плоской плоскости, сэмплируем DEM в полученной точке, обновляем высоту, повторяем до сходимости по толерантности. Это классическая итерация для прямого geolocation на рельефе (используется, например, в ENVI/IDL модуле `IGM` и в ESA SNAP).

#### 3.5 Геодезические преобразования
- ENU → геодезические (lon, lat, h на эллипсоиде WGS84) — функция `pymap3d.enu2geodetic()`.
- Под капотом — точные формулы перехода ECEF↔geodetic (Bowring 1976 / Vermeille 2002), реализованные в [`pymap3d`](pymap3d/src/pymap3d/ecef.py:1). Эллипсоид — WGS84 (a = 6 378 137 м, f = 1/298.257223563).
- При необходимости репроекция CRS — через `pyproj.Transformer(always_xy=True)` (PROJ под капотом).

#### 3.6 Запись в GeoTIFF
- Используется механизм **rasterio geolocation arrays** (`src_geoloc_array=(lon, lat)`): мы передаём GDAL не аффинку, а две 2D-сетки координат на каждый исходный пиксель. GDAL/rasterio `reproject(..., resampling=Resampling.nearest)` сам строит выходную регулярную сетку.
- **Nearest-neighbor — принципиально**: любая bilinear/cubic интерполяция смешает соседние спектры и нарушит физику измерения. Это и есть то самое «спектральная корректность важнее красоты».

### Опорные библиотеки
- `pymap3d` — ENU↔geodetic.
- `pyproj` (PROJ) — репроекция CRS.
- `rasterio` (GDAL) — geolocation arrays + GeoTIFF writer.
- `numpy` — векторизация поворотов и пересечений.

### На чём акцентировать в выступлении
1. Pushbroom ≠ обычный кадр — у каждой строки своя поза, поэтому SfM-пайплайны (ODM, MicMac) сюда плохо ложатся.
2. FOV — обязательный параметр, дефолта нет: разные объективы гиперспектральных камер дают разный FOV, и ошибка тут масштабирует всю мозаику.
3. Boresight (юстировка IMU↔камера) и `time_offset_s` (рассинхронизация GPS↔matrix trigger) — главные источники систематических ошибок; в коде это явные параметры в advanced-секции.
4. DEM-aware режим решает проблему «лужи» поверх рельефа, но требует DEM в той же или известной CRS.

## 4. Этап 1 — Frame filter

Файл: [`src/frame_filter.py`](src/frame_filter.py:1).

### Что делает
Пробегает по всем входным GeoTIFF-кадрам и помечает заведомо испорченные (резкие повороты, артефакты сенсора, насыщение, выпавшие столбцы) как rejected. Принятые идут в мозаику; reject-аудит сохраняется в `<output>.rejected.csv`.

### Вход / выход
- Вход: список GeoTIFF + порог-параметры (или один из пресетов Permissive / Default / Strict).
- Выход: список «хороших» путей + список rejected с диагностической причиной.

### Три зарегистрированных метода

#### v1 — hard thresholds (по умолчанию)
Эвристика «в лоб», 8 порогов:
- **skew** аффинного преобразования — если кадр повёрнут / скошен (`max(|b|,|d|) / max(|a|,|e|)`);
- **footprint area** относительно медианы по съёмке (`AREA_LO..AREA_HI`);
- **aspect ratio** ширины/высоты;
- **valid fraction** non-NoData в центральном окне `CENTRE_WINDOW × CENTRE_WINDOW`;
- **std** яркости в центре (если ниже `STD_MIN` — кадр «плоский», скорее всего съёмка ушла в тень/блик);
- **saturation fraction** — доля насыщенных пикселей.

Это типовой набор metadata-/statistical QA для оптической ДЗЗ; ровно такие же критерии встречаются в QA-скриптах для Landsat / Sentinel-2 (LASRC, Sen2Cor cloud/saturation masks).

#### v2 — adaptive MAD
Метрика — площадь отпечатка кадра. По всем кадрам считается **MAD (Median Absolute Deviation)**:

```
MAD = 1.4826 · median( |xᵢ − median(x)| )
```

Кадр режется, если `|xᵢ − median(x)| > K · MAD` (K=3 по умолчанию). Множитель **1.4826** — известный «consistency constant» MAD как робастной оценки σ нормального распределения (Rousseeuw & Croux, 1993). Это — стандартный робастный outlier-detector в статистике, нечувствительный к экстремальным значениям (в отличие от mean ± 3σ).

#### v3 — per-band striping / dropout
Идёт по каждому бэнду:
- **dropout fraction** — доля NoData / 0 / насыщенных пикселей в footprint.
- **striping ratio** = `var(средние по столбцам) / var(все валидные пиксели)`. Близко к 1 → почти вся вариация объясняется межстолбцовой разностью → классический столбцовый стрипинг pushbroom-сенсора (хорошо описан в литературе по гиперспектру: Hyperion stripe correction, Datt et al. 2003).

### Опорные библиотеки
- `rasterio` для чтения окон без подгрузки куба целиком;
- `numpy` для статистики.

### Акценты
1. v1 — простой, но требует ручной подгонки под сенсор; пресеты Permissive/Default/Strict — это как раз UX-надстройка для junior-пользователя.
2. v2 — единственный из трёх **адаптивный к конкретному полёту** (нет глобальных порогов).
3. Striping ratio в v3 — нетривиальный диагностический инструмент, его стоит подсветить специалистам по гиперспектру.

## 5. Этап 2 — Mosaic

Файл: [`src/mosaic.py`](src/mosaic.py:1).

### Что делает
Сшивает прошедшие фильтр кадры в единый много-бэндовый GeoTIFF.

### Вход / выход
- Вход: список GeoTIFF (одинаковые CRS и pixel size — иначе валидация падает; есть опциональный `REPROJECT_TO_FIRST` через `rasterio.warp`).
- Выход: основная мозаика + сайд-выходы (`<output>.overlap_count.tif`, `<output>.valid_coverage.tif`, опционально `<output>.sources.tif` для v2).

### Зарегистрированные методы (все спектрально-корректные)

#### v1 — first-write-wins (default)
В зоне перекрытия в каждый выходной пиксель **полностью пишется один первый встреченный исходник** (все бэнды). Никакого смешивания. Реализация — поверх `rasterio.merge.merge()`, но с band-streaming и chunked open (cap = 256 одновременно открытых файлов, чтобы не упереться в file descriptor limit). По спектру результат идентичен какому-то одному оригинальному пикселю.

#### v2 — best pixel by distance-to-edge (recommended)
Для каждого выходного пикселя выбирается **тот исходник, у которого этот пиксель находится дальше всего от края своего footprint**. Дистанция считается через [`scipy.ndimage.distance_transform_edt`](https://docs.scipy.org/doc/scipy/reference/generated/scipy.ndimage.distance_transform_edt.html) (Euclidean Distance Transform — алгоритм Felzenszwalb & Huttenlocher 2004 / Maurer et al. 2003). Идея: края кадра — самые «грязные» (виньетирование, искажения объектива, неполный свет на матрицу), центр — самый надёжный.

После выбора — копируется **весь спектр** этого пиксельного победителя (все бэнды), без смешивания. Опционально пишется `<output>.sources.tif` (uint16 индекс кадра-победителя на пиксель) — это provenance-карта, по ней потом считаются seam-метрики.

#### v3 — VRT-based (gdalbuildvrt)
Тонкая обёртка над `gdal.BuildVRT` + `gdal.Translate`. Использует встроенное правило «highest resolution wins» с nearest resampling. Отдаёт результат, эквивалентный v1 на не-перекрывающихся входах.

### Что **не** реализовано (намеренно)
Ранее были v4 (feathered blending по `distance_transform_edt`) и v5 (histogram match + feather, метод moment-matching: `gain = σ_ref/σ_src`, `offset = μ_ref − gain·μ_src`). Они были удалены 2026-05-06 как нарушающие spectral fidelity policy. Это хороший момент для разговора про trade-off «глаз vs физика».

### Опорные библиотеки
- `rasterio.merge`, `rasterio.warp` — слияние и репроекция.
- `scipy.ndimage.distance_transform_edt` — для v2.
- GDAL (`osgeo.gdal`) — для v3 / VRT.

### Акценты
1. Все три метода **never mix spectra** — каждый выходной пиксель приходит ровно из одного исходного кадра.
2. v2 (best-pixel) — рекомендуемый: избавляет от типичного артефакта v1, когда «первый по списку» оказывается с виньеткой по краю.
3. Provenance-растр `sources.tif` — недооценённый инструмент: позволяет численно мерить «насколько швы заметны» (см. этап 4).

## 6. Этап 3 — Fill nodata (коронка проекта)

Файл: [`src/fill_nodata.py`](src/fill_nodata.py:1).

### Что делает
Заполняет пропуски (NoData / NaN) внутри мозаики научно обоснованной интерполяцией. Это основной алгоритмический вклад проекта — на нём максимум акцента.

### Вход / выход
- Вход: мозаика + опциональная маска (или авто-сгенерированная), параметры `MAX_DISTANCE`, `SMOOTHING_ITERATIONS`, `FILL_ONLY_INTERIOR`, `MAX_INTERIOR_GAP_PX`.
- Выход: заполненный GeoTIFF + `<output>.fillmask.tif` (3-state: 0=original, 1=filled, 2=outside).

### Главное: footprint-aware mask (не заливаем «пустоту» снаружи)

Это ключевой нюанс: разница между «дыра внутри пролёта» и «снаружи никто не летал» — принципиальная. Нельзя выдумывать данные там, где их физически не было.

Реализация в [`write_interior_fill_mask()`](src/fill_nodata.py:92):
1. По всем бэндам строится **validity mask** (union finite-пикселей).
2. **Топологически замкнутые дыры** определяются через `scipy.ndimage.binary_fill_holes` — это flood-fill от границы растра по invalid-пикселям; всё, что **не** достигнуто заливкой извне, — это и есть «внутренние» дыры.
3. Опциональное **morphological closing** на `MAX_INTERIOR_GAP_PX` итераций (`binary_closing` = dilation N раз → erosion N раз). Это нужно, чтобы захватить узкие щели, касающиеся края растра, которые binary_fill_holes сам по себе не считает «внутренними». Бриджит дырки шириной до ~2N пикселей.
4. Маска делается 3-state: `0 = было валидно`, `1 = надо заполнить`, `2 = снаружи (не заполнять никогда)`.

Бенчмарк из проекта (см. `project_review.md`): включение `MAX_INTERIOR_GAP_PX=50` улучшило MEAN_RMSE с 0.071 до 0.0039 (≈18×) и PSNR с 28 до 51 дБ. Это — главное демонстрируемое улучшение качества.

### Сам алгоритм заполнения

#### v3 — `gdal.FillNodata` (default, native C)
Это **тот же алгоритм, что и в QGIS «Fill nodata»** и в утилите `gdal_fillnodata.py`. Идея:

1. Для каждой NoData-точки в радиусе `MAX_DISTANCE` пикселей в **четырёх квадрантах** (NW, NE, SW, SE) ищется ближайший валидный пиксель.
2. Найденные кандидаты комбинируются по **inverse distance weighting (IDW)** с показателем 2:

```
v(p) = Σᵢ wᵢ · vᵢ  /  Σᵢ wᵢ ,    wᵢ = 1 / dᵢ²
```

3. После этого N раз прогоняется 3×3 masked-mean smoothing — он сглаживает резкие переходы на границах квадрантов.

Поиск 4 квадрантных кандидатов реализован двумя проходами raster sweep (top-down → собирает NW/NE, bottom-up → SW/SE). Это классический O(H·W) алгоритм, описанный в исходниках GDAL ([gdal/alg/gdalfillnodata.cpp](https://github.com/OSGeo/gdal)). Научно — это вариация **Shepard's method** (Shepard 1968, "A two-dimensional interpolation function for irregularly-spaced data"), один из самых старых и устойчивых deterministic-интерполяторов в геостатистике.

#### v2 — pure-Python re-implementation
Тот же алгоритм, написанный на чистом numpy в `fill_nodata()` ([`src/fill_nodata.py:466`](src/fill_nodata.py:466)). Зачем: возможность тестировать без C-зависимости, плюс fallback, если v3 свалится. Реализация — векторизованные quadrant sweeps (см. [`_scan_quadrants()`](src/fill_nodata.py:354)): для каждой строки делаются два проходка `np.maximum.accumulate / np.minimum.accumulate` (West / East), плюс per-column персистентные трекеры, которые «протаскивают» лучший кандидат с предыдущих строк по диагонали. Это даёт квадрантный поиск без явного 2D BFS.

### Почему именно IDW по 4 квадрантам, а не Kriging / Telea / Navier–Stokes

- **Kriging / IDW произвольной формы** — переусложнение для растровой задачи: требует variogram-fitting, тяжёл по времени, на дырах в десятки тысяч пикселей не выживет. Для гиперспектра, где надо обработать ~200 бэндов, это неприемлемо по бюджету.
- **Telea (FMM-based inpainting), Navier–Stokes (Bertalmio et al. 2001)** — это computer vision методы, оптимизированные для **визуальной** реставрации фотографий: восстанавливают **градиенты** и **изофоты**, минимизируя видимость заплатки. Но они меняют значения вокруг дыры (smooth-out), что недопустимо при сохранении физического измерения. Также они не масштабируются на N-band cube консистентно.
- **4-quadrant IDW** — компромисс: симметричный по направлениям (нет bias в сторону одного источника), не трогает оригинальные пиксели, легко параллелится по бэндам, имеет detection-радиус (`MAX_DISTANCE`) — за его пределами пиксель остаётся NoData (важно: алгоритм **не выдумывает** данные слишком далеко от валидных).

Формула IDW в общем виде (Shepard):

```
v̂(x) = Σᵢ vᵢ / d(x, xᵢ)ᵖ  /  Σᵢ 1 / d(x, xᵢ)ᵖ ,    p = 2
```

Симметричный выбор по 4 квадрантам гарантирует, что если валидные пиксели есть со всех сторон — все стороны вносят вклад; если только с одной — дыра заполняется экстраполяцией с одной стороны (без артефакта «волнового фронта» наблюдаемого, например, у простого FMM).

### Опорные библиотеки
- GDAL (`gdal.FillNodata`) — основной backend.
- `scipy.ndimage.binary_fill_holes`, `binary_closing`, `label` — для маски и метрик.
- `numpy` — для v2 и box-filter сглаживания.

### Performance
- **v3 в 10–100× быстрее v2** на боевом размере (нативный C);
- **windowed/tiled mode** (`TILE_SIZE`): обрабатывает по плиткам с гало `MAX_DISTANCE + SMOOTHING_ITERATIONS`, чтобы результат был байт-в-байт равен whole-band;
- **per-band parallel** через `ThreadPoolExecutor` (`N_WORKERS`); специально не ProcessPool — чтобы под Windows не пере-импортировать QGIS в воркерах.

### Метрики дыр (Phase 2.4)
- `n_gap_regions` — число несвязных дыр (через `scipy.ndimage.label` + 4-connectivity);
- `largest_gap_px`, `largest_gap_area_m2` — размер крупнейшей дыры (площадь — из geotransform).

### Акценты
1. **Footprint-aware = главный quality win проекта** (×18 по RMSE). Без этого алгоритм бы заполнял всё подряд, в том числе «фон космоса» снаружи пролёта.
2. **3-state fillmask** — это provenance: можно потом отдельно посмотреть метрики на оригинальных и на заполненных пикселях.
3. **Shepard / 4-quadrant IDW** — это не выдумка, это backend GDAL/QGIS, спектрально-нейтральный (vs Telea / Navier-Stokes из CV).
4. Радиус поиска `MAX_DISTANCE` — это «честность» алгоритма: не выдумываем данные дальше, чем имеем право.

## 7. Этап 4 — Mosaic quality

Файл: [`src/mosaic_quality.py`](src/mosaic_quality.py:1).

### Что делает
Численно сравнивает мозаику с эталоном (например, ручной мозаикой того же полёта или внешним опорным растром) и выдаёт отчёт.

### Вход / выход
- Вход: REFERENCE + MOSAIC (+ опционально `<output>.sources.tif` для seam-метрик и `<output>.fillmask.tif` для filled-only метрик).
- Выход: текстовый отчёт + опционально JSON, набор `QgsProcessingOutputNumber` (значений) на выходе алгоритма.

### Метрики

#### Per-band (mean / worst / 5-й перцентиль)
- **RMSE, MAE** — стандартные L2 / L1 ошибки (lower is better).
- **PSNR** — `10 · log₁₀(MAX² / MSE)`, в дБ. Нормализован по динамическому диапазону бэнда. Может «врать» на тёмных бэндах (низкий MAX → низкий PSNR при той же абсолютной ошибке).
- **SSIM** (Wang et al. 2004, "Image Quality Assessment: From Error Visibility to Structural Similarity") — структурная похожесть, чувствительна к мозаичным швам, которые pixel-wise метрики недооценивают. Через `scikit-image`.

#### Whole-cube
- **SAM (Spectral Angle Mapper)** — главная метрика для гиперспектра (Kruse et al. 1993, AVIRIS). Угол между спектрами как векторами в N-мерном пространстве:

```
SAM(p, q) = arccos( ⟨p, q⟩ / (‖p‖ · ‖q‖) )
```

Инвариантна к масштабу (не реагирует на разницу в освещённости / альбедо), реагирует только на форму спектра. В коде усредняется по пикселям, валидным во **всех** бэндах. Выход — в радианах и в градусах (`SAM_DEG`).

#### Coverage / fill / seam
- `coverage_ratio`, `filled_pixel_ratio`, `nodata_fraction_per_band`;
- `*_filled_only`, `*_overlap_only` — те же метрики на разных подмножествах (отдельно по заполненным, отдельно по перекрытию);
- `n_gap_regions`, `largest_gap_px`;
- **seam consistency** ([`compute_seam_consistency()`](src/mosaic_quality.py:1)): ходит по 4-связным соседям пикселей, у которых разный `sources.tif` ID (т.е. шов между двумя кадрами), и считает абсолютные разности → `SEAM_MEAN`, `MEDIAN`, `P95`, `MAX`. Прямое численное измерение «насколько шов виден».

### Подводный камень
Reference и mosaic могут иметь разный extent / pixel grid. В коде reference `gdal.Warp`-ится в память на сетку мозаики (`format="MEM"`, `resampleAlg="near"`) — иначе сравнивать нечего.

### Опорные библиотеки
- `osgeo.gdal` (Warp + ввод-вывод);
- `scikit-image` (SSIM) — опциональная зависимость;
- `numpy` — RMSE/MAE/PSNR/SAM.

### Акценты
1. Для гиперспектра **SAM — главная метрика**, не RMSE: спектр — это форма, а не сумма яркостей.
2. WORST / P05 диагностика по бэндам — позволяет находить «битые» каналы (в README пример: bands 38, 138, 202 имеют разные failure modes).
3. Seam-consistency — численное доказательство того, что выбранный mosaic-метод (v1 vs v2) реально лучше или хуже на швах.

## 8. Что можно сказать в заключение

- Проект — это маленький, но методологически честный пайплайн direct georeferencing + mosaic + gap-fill для пользовательской гиперспектральной съёмки с БПЛА.
- Главное архитектурное решение — **spectral fidelity policy**: каждый pipeline-шаг проектировался так, чтобы оригинальные пиксельные значения не перемешивались. В мозаике — first-write-wins / best-pixel вместо feathering. В заполнении — Shepard IDW по 4 квадрантам с footprint-маской вместо Telea/Kriging.
- Главный quality win — **footprint-aware mask** с морфологическим closing: не выдумываем данные снаружи отпечатка пролёта.
- Главный научный фундамент: pushbroom collinearity → ENU rotations → WGS84 geodetic (`pymap3d`); Shepard's IDW 1968 в реализации GDAL для gap-fill; SAM (Kruse 1993) и SSIM (Wang 2004) для оценки качества; MAD (Rousseeuw & Croux 1993) для адаптивной фильтрации кадров.

### Что показать на слайдах
1. До/после fill_nodata на одном бэнде с подсвеченной 3-state маской.
2. Растр `sources.tif` (provenance) + сравнение seam-метрик v1 vs v2.
3. Таблица бенчмарка `MAX_INTERIOR_GAP_PX=0` vs `=50` (RMSE 0.071 → 0.0039).
4. Geometry-схема: связанная (body) система → ENU → geodetic, с тремя углами roll/pitch/yaw.

# `gaps_filler` — шпаргалка для устного выступления (~10 мин)

> Тезисы. Аудитория смешанная. Говорить **своими словами**.

---

## 1. Введение (≈1 мин)

**Образ:** дрон с гиперспектральной камерой летает над полем как сканер в супермаркете — снимает узкими полосками. Из этих полосок надо собрать **одну большую карту** без дыр.

- Гиперспектральные камеры на БПЛА → ~**200 спектральных каналов** (намного больше, чем RGB).
- Каждый пиксель — это не цвет, а **«отпечаток вещества»** (трава, вода, металл — у каждого свой спектр).
- Плагин для **QGIS** (популярная ГИС-программа) — пайплайн из 5 этапов.
- **Главный принцип:** *честность данных важнее красоты картинки*. Видимые швы — ОК. Подкрашивать пиксели — НЕ ОК.

🎯 **Триггер-фраза:** «Мы не рисуем карту — мы её **измеряем**.»

---

## 2. Чтение входных данных (≈30 сек)

**Образ:** камера отдаёт «сырьё» — куб данных + журнал полёта (где была, куда смотрела, когда).

- Формат **ENVI** (стандарт для гиперспектра) + телеметрия GPS/IMU + временные метки строк.
- Подводный камень: **GPS и камера тикают в разных шкалах времени** — выравниваем по относительному времени.

---

## 3. Фильтрация плохих кадров (≈1 мин)

**Образ:** перед склейкой выкидываем заведомо бракованные снимки — как при сборке панорамы на телефоне.

- **Что ищем:** перекошенные кадры, тёмные/пересвеченные, со сбоями сенсора (выпавшие столбцы — «полоски»).
- **3 метода** на выбор:
  - простые **жёсткие пороги** (8 параметров),
  - **адаптивный** — подстраивается под конкретный полёт через **MAD** (робастная статистика, не боится выбросов; основа — *Rousseeuw & Croux, 1993*),
  - **по-канальный** — ищет полосатость в каждом из 200 спектральных каналов.
- Все отбракованные → в **CSV-аудит**: видно, **за что** именно выкинули.

---

## 4. Геопривязка кадров (≈1.5 мин)

**Образ:** камера снимает строчки. Зная, **где дрон был** и **куда смотрел**, для каждой строчки считаем — на какую точку земли она попала.

- Сенсор **pushbroom** (как сканер): одна строка = один момент времени, у каждой строки **своя поза**.
- Алгоритм:
  1. Из IMU/GPS интерполируем позу под каждую строку (**roll/pitch/yaw**).
  2. От пикселя строим **луч в пространстве**.
  3. Пересекаем луч с землёй — плоскость или **DEM** (цифровая модель рельефа).
  4. Координаты → широта/долгота на **WGS84** (через библиотеку `pymap3d`).
- **Научная база:** классические уравнения коллинеарности из аэрофотограмметрии (Lillesand, Kiefer; ASPRS Manual of Photogrammetry).
- При записи — **только nearest-neighbor**: любая «гладкая» интерполяция смешает спектры → запрещено.

🎯 **Триггер:** «Каждый пиксель помнит, **в какой момент** и **под каким углом** его сняли.»

---

## 5. Сборка мозаики (≈1 мин)

**Образ:** склеиваем кадры в одну карту. Главный вопрос — **что писать в зоне перекрытия двух кадров**.

- **Жёсткое правило:** в перекрытии берём **один кадр-победитель целиком**, без смешивания. Спектр — это измерение, его **нельзя усреднять**.
- 3 метода:
  - **first-write-wins** — кто пришёл раньше;
  - **best-pixel** (рекомендуемый) — побеждает кадр, у которого этот пиксель **дальше от своего края** (центр кадра — самая чистая часть, края портит виньетирование);
  - **VRT** — лёгкая GDAL-обёртка.
- Сохраняем **карту авторства** (`sources.tif`) — какой кадр выиграл в каждой точке. Потом по ней меряем **видимость швов**.

---

## 6. **Заполнение пропусков — главный этап** (≈2.5 мин)

**Образ:** в мозаике остались **дыры** — там, где данные испорчены или кадры не сошлись. Аккуратно их **штопаем**, но **не выходим за край пролёта** — там данных физически не было.

### Главный трюк: **footprint-aware маска** (3 состояния)

- `0` — пиксель **оригинальный** (не трогаем);
- `1` — **дыра внутри** пролёта → заполняем;
- `2` — **снаружи** пролёта → НЕ заполняем никогда.

Внутренние дыры находим через **flood-fill** (`scipy.binary_fill_holes`) + **морфологическое закрытие** для узких щелей у края.

### Эффект — **главный wow-результат проекта:**
> Включение умной маски улучшило **RMSE в ~18 раз** (0.071 → 0.0039), **PSNR с 28 до 51 дБ**.

### Сам алгоритм заполнения

- **Метод Шепарда (Shepard, 1968)** — взвешивание по обратному квадрату расстояния. Тот же алгоритм, что в `gdal.FillNodata` и в стандартном QGIS.
- Хитрость: ищем соседей **в 4 квадрантах** (NW/NE/SW/SE) — заполнение **симметричное**, без перекоса в одну сторону.
- **Не используем** Telea / Navier-Stokes (это методы реставрации **фотографий** — они портят пиксельные значения ради визуала).
- Есть радиус поиска `MAX_DISTANCE`: дальше **не выдумываем** — это «честность» алгоритма.

🎯 **Триггер:** «Я не дорисовываю данные. Я их **аккуратно интерполирую** — и **только там, где имею право**.»

---

## 7. Оценка качества (≈1 мин)

**Образ:** сравниваем нашу мозаику с **эталоном** — насколько мы близки к «правильному ответу».

- **RMSE / MAE / PSNR** — обычные ошибки попиксельно.
- **SSIM** — структурное сходство (Wang, 2004) — ловит швы, которые попиксельные метрики **пропускают**.
- **SAM (Spectral Angle Mapper)** — **главная метрика для гиперспектра** (Kruse, 1993): **угол между спектрами** как векторами. Не реагирует на яркость, реагирует на **форму** спектра.
- **Seam-метрика:** прямо считаем разности яркости через швы между кадрами — **численно** доказываем, что best-pixel лучше first-write-wins.

🎯 **Триггер:** «Для гиперспектра RMSE — не главное. Главное — **форма** спектра.»

---

## 8. Заключение (≈30 сек)

- Получился **рабочий пайплайн в QGIS**: от сырого `.bil`-куба до заполненной мозаики с числовой оценкой качества.
- **Чем горжусь:**
  1. **Spectral fidelity policy** — везде сохраняем оригинальные значения пикселей.
  2. **Footprint-aware заполнение** — не выдумываем данные снаружи пролёта (×18 по качеству).
  3. **Метрики провенанса** (`sources.tif` + seam consistency) — швы из «ощущения» стали **числом**.
- **Куда дальше:** калибровка boresight (несоосность IMU↔камера), интеграция реального DEM, CLI-режим вне QGIS.

🎯 **Финал:** «Маленький проект, но **методологически честный**. Спасибо.»

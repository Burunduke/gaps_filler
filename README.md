# Hyperspectral gaps filler

Плагин QGIS для заполнения пропусков (NoData) в растрах и для подготовки ортофотопланов из гиперспектральных снимков с дрона **PIKA-L**.

Плагин решает две связанные задачи:

1. **Заполнение пропусков** в одном растре — Python-порт алгоритма GDAL `FillNodata` (взвешивание по обратному расстоянию от ближайших валидных пикселей в четырёх квадрантах + опциональное сглаживание).
2. **Конвейер для PIKA-L** из трёх стадий:
   1. Отбраковка плохих кадров (фильтр по эвристикам).
   2. Мозаицирование оставшихся кадров по правилу «первый записал — выиграл» (`first-write-wins`).
   3. Заполнение оставшихся NoData в каждом канале результирующей мозаики.

Имя плагина: **Hyperspectral gaps filler**, версия **0.2** (см. [`metadata.txt`](metadata.txt:1)).

---

## Установка

Плагин устанавливается стандартным способом QGIS: *Plugins → Manage and Install Plugins…* → выбрать плагин из списка либо установить из ZIP. После установки алгоритмы появятся в *Processing Toolbox* в группе **Raster analysis**.

### Зависимости

- `numpy`
- `rasterio`
- GDAL — поставляется вместе с QGIS, отдельно ставить не нужно.
- Python 3.x (используется QGIS).

Стадии Python-кода ([`fill_nodata.py`](fill_nodata.py:1), [`frame_filter.py`](frame_filter.py:1), [`mosaic.py`](mosaic.py:1)) намеренно не импортируют `osgeo.gdal` и `qgis` — они работают через `rasterio` и stdlib.

## Алгоритмы в Processing Toolbox

Все четыре алгоритма находятся в группе **Raster analysis**.

### Filter bad frames

Реализован в [`frame_filter_algorithm.py`](frame_filter_algorithm.py:1). Прогоняет эвристику отбраковки PIKA-L по входным растрам и копирует «выживших» в указанную папку; в журнал и (опционально) в текстовый отчёт пишутся причины отбраковки.

Используйте, когда нужно отдельно проверить качество набора кадров перед мозаицированием — например, чтобы вручную просмотреть отбракованные.

#### Эвристики (порядок проверки в [`frame_filter.py`](frame_filter.py:1))

1. **Перекос/поворот аффинного преобразования** — соотношение недиагональных и диагональных компонент `transform`.
2. **Площадь следа кадра** относительно медианы по всем входам.
3. **Соотношение сторон** (длинная / короткая).
4. **Центральное окно полосы 1**: доля валидных пикселей, доля насыщенных (для целочисленных типов) и стандартное отклонение.

#### Параметры

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `INPUT_LAYERS` (Input frames) | список растров | — | Кадры PIKA-L для проверки. |
| `OUTPUT_FOLDER` (Output folder for kept frames) | папка | — | Куда копировать кадры, прошедшие отбор. |
| `REPORT` (Rejection report) | файл `.txt`, опц. | — | Текстовый отчёт со списком принятых/отбракованных и причинами. |
| `SKEW_MAX` (Max skew (rotation tolerance)) | Double, 0.0–1.0 | `0.05` | Что измеряется: относительный перекос аффинного преобразования (`max(|b|,|d|) / max(|a|,|e|)`). Когда менять: **увеличить**, если кадры с лёгким поворотом отбрасываются, **уменьшить** — если в выборке остаются явно повёрнутые. |
| `AREA_LO` (Min area ratio vs. flight median) | Double, 0.0–1.0 | `0.5` | Что измеряется: нижний порог отношения площади кадра к медианной площади по полёту. Когда менять: **уменьшить** (например, до 0.3), если законные кадры на краях полосы съёмки отбрасываются по «маленькой» площади. |
| `AREA_HI` (Max area ratio vs. flight median) | Double, 1.0–10.0 | `2.0` | Что измеряется: верхний порог того же отношения. Когда менять: **увеличить**, если законные крупные кадры режутся; **уменьшить**, если в выборку попадают «раздутые» кадры. |
| `ASPECT_MAX` (Max aspect ratio (long / short side)) | Double, 1.0–10.0 | `2.0` | Что измеряется: отношение длинной стороны кадра к короткой. Когда менять: **увеличить**, если форма кадров PIKA-L заведомо вытянута и порог режет годные кадры. |
| `CENTRE_WINDOW` (Centre window size (pixels)) | Integer, 4–4096 | `64` | Что измеряется: размер квадратного окна по центру кадра, на котором делаются проверки валидности/насыщения/дисперсии. Когда менять: **увеличить**, если центр сцены содержит крупные NoData-области и оценка нерепрезентативна. |
| `MIN_VALID_FRACTION` (Min fraction of valid pixels in centre) | Double, 0.0–1.0 | `0.5` | Что измеряется: минимальная доля не-NoData пикселей в центральном окне. Когда менять: **уменьшить**, если в центрах легитимных кадров много NoData, и они отбрасываются. |
| `STD_MIN` (Min std-dev of centre (low-variance reject)) | Double, 0.0–1e6 | `1.0` | Что измеряется: минимальное СКО яркости в центральном окне (отбрасывает «мёртвые»/однотонные кадры). Когда менять: **уменьшить**, если съёмка по природе своей низкоконтрастная (вода, снег) и кадры режутся. |
| `SATURATION_FRACTION` (Max saturated-pixel fraction in centre) | Double, 0.0–1.0 | `0.95` | Что измеряется: максимально допустимая доля пикселей в центре, равных максимуму типа данных (только для целочисленных типов). Когда менять: **уменьшить**, если хочется агрессивнее отсекать пересвет; **увеличить** — если съёмка выполнена близко к насыщению намеренно. |

### Mosaic frames (first-write-wins)

Реализован в [`mosaic_algorithm.py`](mosaic_algorithm.py:1). Склеивает уже отфильтрованные кадры в один GeoTIFF; в местах перекрытия сохраняется значение из **первого** кадра, дописавшего пиксель. Все входы должны иметь одинаковую CRS и одинаковый размер пикселя.

Используйте после `Filter bad frames`, либо когда у вас уже есть набор «чистых» кадров и нужно собрать из них единый растр, не запуская весь конвейер.

#### Параметры

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `INPUT_LAYERS` (Input frames) | список растров | — | Кадры с одинаковой CRS и пиксельным шагом. |
| `OUTPUT` (Mosaic output) | GeoTIFF | — | Файл результирующей мозаики. |

### Fill nodata

Реализован в [`gaps_filler_algorithm.py`](gaps_filler_algorithm.py:1). Заполняет NoData в одной полосе растра по правилу обратного расстояния от четырёх ближайших валидных пикселей (по одному на квадрант) с опциональным 3×3-сглаживанием. Геопривязка, проекция и значение NoData в выходе сохраняются. Выход — однополосный GeoTIFF (как у GDAL `FillNodata`).

Используйте, когда нужно «залатать» уже готовый растр (мозаику или DEM), не запуская стадии фильтра/мозаики.

#### Параметры

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `INPUT` (Input raster) | растр | — | Любой растр, читаемый GDAL. |
| `BAND` (Band number) | Integer | `1` | Номер обрабатываемой полосы. |
| `DISTANCE` (Maximum distance (in pixels) to search out for values to interpolate) | Integer, ≥0 | `10` | Максимальный радиус поиска валидных соседей в пикселях. |
| `ITERATIONS` (Number of smoothing iterations to run after the interpolation) | Integer, ≥0 | `0` | Сколько проходов 3×3-сглаживания применить после интерполяции. |
| `MASK_LAYER` (Validity mask) | растр, опц. | — | Маска валидности (ненулевое = валидно). |
| `OUTPUT` (Filled) | GeoTIFF | — | Файл результата. |

### Hyperspectral pipeline (filter, mosaic, fill)

Реализован в [`hyperspectral_algorithm.py`](hyperspectral_algorithm.py:1). Сквозной конвейер PIKA-L: отбраковывает плохие кадры, мозаицирует оставшиеся правилом `first-write-wins` и заполняет NoData во **всех** полосах результата.

Используйте, когда у вас на входе сырая пачка кадров с дрона и нужно одной кнопкой получить готовую мозаику с заполненными пропусками.

#### Параметры

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `INPUT_LAYERS` (Input frames) | список растров | — | Кадры PIKA-L. |

| `SMOOTHING_ITERATIONS` (Number of smoothing iterations to run after the interpolation) | Integer, ≥0 | `0` | Число проходов сглаживания после интерполяции. |
| `SKEW_MAX` (Max skew (rotation tolerance)) | Double, 0.0–1.0 | `0.05` | См. одноимённый параметр в *Filter bad frames*. |
| `AREA_LO` (Min area ratio vs. flight median) | Double, 0.0–1.0 | `0.5` | См. одноимённый параметр в *Filter bad frames*. |
| `AREA_HI` (Max area ratio vs. flight median) | Double, 1.0–10.0 | `2.0` | См. одноимённый параметр в *Filter bad frames*. |
| `ASPECT_MAX` (Max aspect ratio (long / short side)) | Double, 1.0–10.0 | `2.0` | См. одноимённый параметр в *Filter bad frames*. |
| `CENTRE_WINDOW` (Centre window size (pixels)) | Integer, 4–4096 | `64` | См. одноимённый параметр в *Filter bad frames*. |
| `MIN_VALID_FRACTION` (Min fraction of valid pixels in centre) | Double, 0.0–1.0 | `0.5` | См. одноимённый параметр в *Filter bad frames*. |
| `STD_MIN` (Min std-dev of centre (low-variance reject)) | Double, 0.0–1e6 | `1.0` | См. одноимённый параметр в *Filter bad frames*. |
| `SATURATION_FRACTION` (Max saturated-pixel fraction in centre) | Double, 0.0–1.0 | `0.95` | См. одноимённый параметр в *Filter bad frames*. |

## Расшифровка причин отбраковки в журнале

При запуске *Filter bad frames* (или сквозного конвейера) на каждый отбракованный кадр в журнал пишется строка вида `REJECTED <имя файла>: <причина>`. Ниже — все возможные причины, как их формирует [`frame_filter.py`](frame_filter.py:1).

| Строка в логе | Что это значит | Какой порог трогать |
|---|---|---|
| `skewed transform (skew=X > Y)` | Аффинное преобразование кадра имеет слишком большой перекос/поворот. | Увеличить `SKEW_MAX`. |
| `abnormal area (area=X, allowed=[lo, hi])` | Площадь следа кадра сильно отличается от медианы по полёту. | Расширить интервал: уменьшить `AREA_LO` и/или увеличить `AREA_HI`. |
| `abnormal aspect ratio (ar=X > Y)` | Кадр слишком вытянут (длинная сторона / короткая больше порога). | Увеличить `ASPECT_MAX`. |
| `mostly nodata in centre (valid=X < Y)` | В центральном окне доля валидных пикселей ниже порога. | Уменьшить `MIN_VALID_FRACTION` или увеличить `CENTRE_WINDOW`. |
| `low variance centre (std=X < Y)` | Центр кадра слишком однороден (низкое СКО). | Уменьшить `STD_MIN`. |
| `saturated centre (sat=X > Y)` | В центре кадра слишком много пикселей, равных максимуму типа данных (пересвет). | Увеличить `SATURATION_FRACTION`. |

## Типичный сценарий: «у меня все кадры отбраковались»

1. Запустить *Filter bad frames* (или *Hyperspectral pipeline*) **с дефолтами**, ничего не трогая.
2. Открыть *Log* в окне Processing — там будут строки `REJECTED <файл>: <причина>`.
3. Если задали отчёт `REPORT`, открыть его — в нём перечислены все отбракованные кадры с причинами.
4. Найти **доминирующую** причину (например, у 90% кадров одна и та же фраза).
5. По таблице выше определить порог, который её контролирует, и **аккуратно ослабить** его (например, `MIN_VALID_FRACTION` с `0.5` до `0.3`).
6. Запустить алгоритм повторно с новым значением.
7. Повторять шаги 4–6 до приемлемого процента «выживших». Если ослабление одного порога не помогает — проверьте следующую по частоте причину; не ослабляйте сразу всё.

## Ограничения

- Все входные кадры должны иметь одинаковую CRS и одинаковый размер пикселя — это требование стадии мозаицирования ([`mosaic.py`](mosaic.py:1)).
- Перепроецирование и ресемплинг **не выполняются**.
- Перекрытия в мозаике разрешаются по правилу **«первый записал — выиграл»** (`first-write-wins`); фезеринг и усреднение пока не реализованы.
- Стадия отбраковки рассчитана на кадры PIKA-L; для других сенсоров пороги, скорее всего, придётся подбирать заново.
- Автоматических тестов в проекте нет.

## Project overview

`gaps_filler` is a QGIS 3 plugin (declared in [`metadata.txt`](metadata.txt:1), `qgisMinimumVersion=3.14`, `experimental=True`) targeted at the structured processing of **hyperspectral and UAV-derived raster data**. Originating as a Plugin Builder skeleton, it has matured into a QGIS Processing-framework provider with a clean separation between two distinct entities:

1. **Six QGIS Processing algorithms** exposed in the Toolbox under *Hyperspectral gaps filler → Raster analysis*. Each is a thin [`QgsProcessingAlgorithm`](https://api.qgis.org/api/classQgsProcessingAlgorithm.html) wrapper that builds the user-facing dialog, validates parameters, plumbs progress / cancellation into the core, and applies post-processing styling to output layers.
2. **A research-oriented computational pipeline** for hyperspectral and UAV-derived raster cubes, implemented as a pure-Python core in [`src/`](src/__init__.py:1). The core has no Qt / QGIS dependency (only `numpy`, `osgeo.gdal`, `rasterio`, optional `scipy` / `skimage` / `spectral` / `pymap3d` / `pyproj`) and is reusable from CLI scripts, notebooks and unit tests.

The six algorithms cover the canonical hyperspectral / UAV workflow:

```
raw .bil cube ──▶ airborne georef ──▶ frames ──▶ frame filter ──▶ mosaic ──▶ fill_nodata ──▶ filled mosaic
                    (Stage Raw)                    (Stage A)      (Stage B)   (Stage C)
                                                                                          ──▶ mosaic_quality (vs reference)
```

The end-to-end pipeline algorithm chains Stage A → B → C; the remaining algorithms are also useful as standalone tools and as building blocks in QGIS Model Builder.

## Project policy — data correctness over visual appearance

The plugin is governed by an explicit spectral-fidelity policy: **reliability and correctness of pixel values takes precedence over the visual smoothness of the mosaic.** Visible seams in overlap regions are accepted as the cost of preserving exact per-pixel spectra. All currently registered mosaic methods (`v1_first_write_wins`, `v2_best_pixel`, `v3_vrt`) are spectrally faithful — each output pixel originates from exactly one source frame, with no mixing, feathering or histogram matching. Index 0 of [`MOSAIC_METHODS`](src/methods.py:88) must always remain a spectrally-faithful path; visual-only variants (feathering, blending, histogram matching) are explicitly prohibited from registration. The detailed policy statement and the historical removal of `v4_feather` / `v5_histmatch_feather` is preserved further down this document.

## Current state

The plugin is **published as experimental** with `qgisMinimumVersion = 3.14` ([`metadata.txt`](metadata.txt:1)), accurately reflecting the modern Processing parameter API actually relied upon. The pure-Python core lives in [`src/`](src/__init__.py:1) and is consumed by the workspace-root QGIS wrappers via `from .src import …`. The user-facing reference is [`README.md`](README.md:1), which describes the six algorithms, the side-outputs convention and the spectral-fidelity policy. [`pb_tool.cfg`](pb_tool.cfg:1) lists `src` in `extra_dirs` so the package ships to QGIS as a unit.

**Method registries** (one entry per implemented version, defined in [`src/methods.py`](src/methods.py:1)):

- [`FRAME_FILTER_METHODS`](src/methods.py:27) — `v1_hard_thresholds` (index 0, default), `v2_adaptive_mad` (per-flight MAD around median footprint area), `v3_per_band` (per-band striping ratio + dropout fraction).
- [`MOSAIC_METHODS`](src/methods.py:88) — `v1_first_write_wins` (index 0, default), `v2_best_pixel` (index 1, recommended; writes `<output>.sources.tif` provenance raster), `v3_vrt` (index 2, lazy GDAL VRT). All are spectrally faithful — see Project policy.
- [`GAP_FILL_METHODS`](src/methods.py:134) — `v3_gdal_fillnodata` (index 0, default, native C), `v2_idw_quadrants` (index 1, pure-Python; used as fallback).

**Side outputs convention** (all written next to `<output>`):

| File | Producer | Role |
|---|---|---|
| `<output>.mosaic.tif` | Pipeline Stage B intermediate | Deleted at the end of a pipeline run. |
| `<output>.fillmask.tif` | [`write_interior_fill_mask()`](src/fill_nodata.py:92) | 3-state mask (0 = original, 1 = filled, 2 = outside); consumed by `mosaic_quality` `*_filled_only` metrics and gap-region statistics. |
| `<output>.sources.tif` | [`mosaic_frames_best_pixel()`](src/mosaic.py:403) | uint16 provenance raster; consumed by [`analyze_sources()`](src/mosaic_quality.py:103) and [`compute_seam_consistency()`](src/mosaic_quality.py:938). |
| `<output>.overlap_count.tif` | All Stage B methods when `emit_coverage_outputs=True` | uint16, per-pixel frame count. |
| `<output>.valid_coverage.tif` | All Stage B methods when `emit_coverage_outputs=True` | uint8 binary mask of pixels covered by ≥ 1 frame. |
| `<output>.rejected.csv` | [`run_pipeline()`](src/pipeline.py:166) | Stage A audit (`path, reason, measured_value, threshold`); a deliverable, not a temp file. |
| `<output>.footprint.geojson` | [`write_footprint_vector()`](src/airborne_georef.py:559) | Flight-line footprint polygon from the raw georeferencing stage. |

**QGIS algorithm parameter behaviour.** Every method dropdown defaults to index 0. When `OUTPUT` is empty (`None`, `""`, `"TEMPORARY_OUTPUT"`), Stage B / Stage C / Pipeline derive a path from the first input's folder (`mosaic.tif` / `<input>_filled.tif` / `filled_mosaic.tif`) and log it. Method-specific knobs (raw v1 thresholds, v2 `K_MAD`, v3 `MAX_DROPOUT_FRAC` / `MAX_STRIPE_RATIO`, Stage C `TILE_SIZE` / `N_WORKERS`, mosaic `EMIT_COVERAGE_OUTPUTS`, raw-stage boresight angles + `TIME_OFFSET_S`) are flagged `FlagAdvanced` so only the relevant controls are visible by default. Mosaic Quality outputs are described above and include the six `SEAM_*` metrics when `SOURCES_PATH` is provided.

## Design constraints by policy

The following behaviours look like limitations on first reading but are intentional consequences of the spectral-fidelity policy or of the deliberately small operational surface. They are documented here so they are not mistaken for backlog items.

- **No implicit reprojection or resampling.** CRS / pixel-size mismatch aborts via [`MosaicInputError`](src/mosaic.py:49) unless the user explicitly opts in via `REPROJECT_TO_FIRST=True`, which routes inputs through `rasterio.warp` into a temp directory. Silent reprojection is prohibited because it would resample spectra.
- **Thresholds are global per run.** Per-flight auto-derivation is offered only through the dedicated `v2_adaptive_mad` filter method ([`filter_frames_adaptive_mad()`](src/frame_filter.py:281)); other methods take the user-supplied or preset values verbatim.
- **No intermediate mosaic caching.** The pipeline's `<output>.mosaic.tif` and `<output>.fillmask.tif` are temp files cleaned by the `try / finally` block in [`run_pipeline()`](src/pipeline.py:166); the standalone Mosaic algorithm remains available when a persisted Stage B output is required.
- **Stage A copies kept frames.** [`FrameFilterAlgorithm`](frame_filter_algorithm.py:44) copies (rather than symlinks) accepted frames into its output folder, so disk usage roughly doubles in exchange for OS-independent behaviour and a self-contained deliverable.
- **Optional dependency surface.** `scipy` (preferred for `binary_fill_holes` / `binary_closing`, pure-numpy fallback exists), `scikit-image` (required for SSIM in [`src/mosaic_quality.py`](src/mosaic_quality.py:1)), `spectral` (lazy-imported by [`src/envi_io.py`](src/envi_io.py:1)), `pymap3d` (used by [`flat_ground_grid()`](src/airborne_georef.py:275) and [`dem_ground_grid()`](src/airborne_georef.py:920)), `rasterio >= 1.3` (for the `dtype=` / `nodata=` kwargs on `rasterio.merge.merge`), `pyproj` (lazy-imported inside [`write_flat_geotiff()`](src/airborne_georef.py:704) and [`dem_ground_grid()`](src/airborne_georef.py:920) only when the destination / DEM CRS differs from `EPSG:4326`). The plugin remains functional with the minimal subset; advanced features degrade gracefully.

## Remaining open questions and backlog

Items in this section are the actually-open work; closed items have been removed rather than annotated as resolved.

- **QGIS wrapper layer location.** The pure-Python core already lives in [`src/`](src/__init__.py:1) with no Qt imports; the second half of the long-discussed `core/` + `qgis/` split — moving the six `*_algorithm.py` wrappers plus [`gaps_filler_provider.py`](gaps_filler_provider.py:1), [`gaps_filler.py`](gaps_filler.py:1), [`__init__.py`](__init__.py:1), [`canvas_styling.py`](canvas_styling.py:1) and [`qgis_helpers.py`](qgis_helpers.py:1) into a sibling `qgis/` package — is deferred until the wrapper module count exceeds ~25 or a second consumer (e.g. a CLI) appears. When scheduled, the move is expected to be a single mechanical rename PR with no new abstractions and no staged refactor.
- **Automated test coverage.** The [`test/`](test/__init__.py:1) tree still contains only Plugin Builder scaffolding (QGIS test app harness, metadata validator, translation smoke tests). The core in [`src/`](src/__init__.py:1) has no unit tests for `mosaic`, `fill_nodata`, `frame_filter`, `pipeline`, `mosaic_quality` or `airborne_georef`, and there are no QGIS-side integration tests exercising the six Processing algorithms end-to-end on a small fixture cube. Adding unit tests for the pure-Python core is the lower-hanging half.
- **CI and QGIS integration testing.** No continuous integration is wired up. A pipeline that runs the pure-Python unit tests on a stock Python, and optionally exercises the Processing wrappers inside a headless QGIS container, would let the `experimental` flag be revisited with evidence rather than by inspection.
- **Packaging and release hardening.** The plugin is shipped via `pb_tool` ([`pb_tool.cfg`](pb_tool.cfg:1)); there is no automated release artefact, no reproducible build step, and no checksum / signing convention. A documented release procedure (build, smoke-test, upload to the QGIS plugin repository) is open work.
- **Licensing.** The repository does not yet carry a top-level `LICENSE` file. A licence choice consistent with the QGIS plugin ecosystem (typically GPL-compatible) needs to be made and committed.
- **Stability flag.** `experimental=True` ([`metadata.txt`](metadata.txt:1)) is retained for now. Promoting the plugin to a non-experimental release should be conditional on CI coverage, packaging hardening and the licence being in place; until then the flag accurately signals the maturity level to users.
- **i18n.** Translation machinery is wired up but no `i18n/*.qm` files exist. Adding at least one non-English translation is open work, but low priority relative to the items above.

## Operational tuning — frame filter thresholds

- Open **"Filter bad frames"** ([`frame_filter_algorithm.py`](frame_filter_algorithm.py:1)) or **"Hyperspectral pipeline"** ([`hyperspectral_algorithm.py`](hyperspectral_algorithm.py:1)). Pick a preset from `THRESHOLD_PRESET` (Permissive / Default / Strict) or leave it on `Custom` to use the eight raw inputs.
- Defaults match the module-level constants in [`src/frame_filter.py`](src/frame_filter.py:1) (`SKEW_MAX=0.05`, `AREA_LO=0.5`, `AREA_HI=2.0`, `ASPECT_MAX=2.0`, `CENTRE_WINDOW=64`, `MIN_VALID_FRACTION=0.5`, `STD_MIN=1.0`, `SATURATION_FRACTION=0.95`).
- Rejection lines in the Processing log embed both the measured value AND the violated threshold, so it is obvious which knob to relax. Example: `"abnormal aspect ratio (ar=2.15 > 2.00)"` → raise `aspect_max`.
- If every frame is rejected, scan the live log for the most common reason and bump the matching threshold (or pick the `Permissive` preset).
- Bigger `centre_window` = more pixels feed the variance / saturation / valid-fraction check (more reliable but slower).

## Engineering evolution

The following thematic sections summarise the engineering trajectory of the project. Earlier revisions of this document maintained a dated per-commit changelog; that ledger has been retired in favour of grouped descriptions of the structural results actually delivered. Per-commit history remains available in the version-control log.

### Method registries and Processing UI consistency

The decisive shift in the QGIS-facing surface was the introduction of three plain-Python registries — [`FRAME_FILTER_METHODS`](src/methods.py:27), [`MOSAIC_METHODS`](src/methods.py:88), [`GAP_FILL_METHODS`](src/methods.py:134), each a list of `{id, label, tooltip, func}` dicts — as the single source of truth for per-stage method selection. Every QGIS Processing algorithm now exposes a `QgsProcessingParameterEnum` for each relevant stage, reads the enum index, looks up the registry entry, logs `method["id"]`, and dispatches through `entry["func"](...)`. The orchestrator [`run_pipeline()`](src/pipeline.py:166) defaults its three method callables from `methods.*[0]["func"]` (via a lazy `from . import methods`) rather than from hard-coded callables, so reordering or replacing the index-0 entry in [`src/methods.py`](src/methods.py:1) propagates without touching the orchestrator. The dry-run path of [`HyperspectralPipelineAlgorithm`](hyperspectral_algorithm.py:1) mirrors the non-dry-run dispatch line-for-line so the v2 / v3 paths cannot drift.

Dialog ergonomics were aligned with the same principle. Method-specific knobs — the eight raw v1 thresholds, the v2 `K_MAD`, the v3 `MAX_DROPOUT_FRAC` / `MAX_STRIPE_RATIO`, Stage C `TILE_SIZE` / `N_WORKERS`, mosaic `EMIT_COVERAGE_OUTPUTS`, raw-stage boresight angles and `TIME_OFFSET_S` — are flagged `QgsProcessingParameterDefinition.FlagAdvanced` so only the relevant controls are visible by default. Threshold presets (`THRESHOLD_PRESETS` in [`src/frame_filter.py`](src/frame_filter.py:1) with [`preset_thresholds()`](src/frame_filter.py:110) lookup) reduce the eight-input dialog to a single dropdown when the user does not need fine control. When `OUTPUT` is empty the three algorithms with a raster destination derive a path from the input folder and log it. RGB rendering of multi-band raster outputs is attached automatically by [`canvas_styling.py`](canvas_styling.py:1) for the Mosaic, Fill NoData, Pipeline and Airborne Georef algorithms. `QgsProcessingAlgorithm.name()` / `displayName()` / `groupId()` and parameter IDs were preserved across all rewordings so saved Model Builder graphs continue to resolve.

### Robustness, diagnostics and side outputs

Stage A / B / C share a common robustness contract. Early validation runs through [`mosaic.validate_inputs()`](src/mosaic.py:58) before Stage A, so CRS / pixel-size / band-count / dtype mismatch fails in seconds with a clear `QgsProcessingException`. An all-NaN-band guard in [`run_pipeline()`](src/pipeline.py:166) fails loudly with the offending band index instead of silently returning all-NaN. Optional CRS reprojection (`reproject_to_first`) routes inputs through `rasterio.warp` into a temp dir when explicitly enabled; the default reproduces previous byte-identical behaviour. A file-descriptor cap [`_MAX_OPEN_SOURCES = 256`](src/mosaic.py:46) protects the mosaic stage on large hyperspectral flights, with cross-chunk first-write-wins preserved through read-modify-write on still-NaN pixels. Cancellation is threaded through every stage via an `is_canceled` callback; `RuntimeError("canceled")` is translated to `QgsProcessingException` in every wrapper.

Stage A produces a `<output>.rejected.csv` audit (`path, reason, measured_value, threshold`); rejection-reason strings reuse a single `"measured vs threshold"` convention across `v1_hard_thresholds`, `v2_adaptive_mad` and `v3_per_band`, so the audit and the [`_parse_reason()`](src/pipeline.py:1) helper remain stable across method changes. Stage B emits two optional coverage rasters — `<output>.overlap_count.tif` (uint16) and `<output>.valid_coverage.tif` (uint8) — written by [`_write_count_raster()`](src/mosaic.py:860); v1 / v2 accumulate counts during the existing per-tile loop, v3 performs a separate pass after VRT translation. The provenance raster `<output>.sources.tif` (uint16, `0` = nodata, `1..N` = 1-based frame index) is written by `v2_best_pixel` and consumed by [`analyze_sources()`](src/mosaic_quality.py:103) and [`compute_seam_consistency()`](src/mosaic_quality.py:938). The temp-file convention `<output>.mosaic.tif` + `<output>.fillmask.tif` is enforced by the `try / finally` block in [`run_pipeline()`](src/pipeline.py:166) so a `KeyboardInterrupt` or QGIS cancellation mid-Stage-B does not leak intermediates.

Mosaic Quality outputs were extended with polarity-aware `WORST_<M>` / `P05_<M>` aggregates and offending band indices `WORST_<M>_BAND` / `P05_<M>_BAND` for each of RMSE / MAE / PSNR / SSIM, plus whole-cube SAM / SAM_DEG accumulated inside the existing per-band loop, and `*_filled_only` / `*_overlap_only` variants gated on the presence of `<output>.fillmask.tif`. The historical "size mismatch" failure (reference vs mosaic differing in extent) is resolved by warping the reference onto the mosaic grid in-memory via `gdal.Warp(format="MEM", resampleAlg="near")`. A JSON serializer [`format_report_json()`](src/mosaic_quality.py:1242) writes the same numbers as the text report through an optional `OUTPUT_REPORT_JSON` parameter, with numpy types, `Path` objects and NaN/Inf handled explicitly. Seam-consistency is exposed via six dedicated outputs (`SEAM_MEAN_ABS_DIFF`, `SEAM_MEDIAN_ABS_DIFF`, `SEAM_P95_ABS_DIFF`, `SEAM_MAX_ABS_DIFF`, `SEAM_PIXEL_COUNT`, `SEAM_LENGTH_PX`) on [`MosaicQualityAlgorithm`](mosaic_quality_algorithm.py:1) when a `SOURCES_PATH` provenance raster is supplied. Gap-region statistics from [`compute_gap_region_metrics()`](src/fill_nodata.py:214) — `n_gap_regions`, `largest_gap_px`, `largest_gap_area_m2` — are computed from the 3-state fillmask using `scipy.ndimage.label` (with a pure-numpy BFS fallback) and reported by both the standalone Fill NoData algorithm and the Mosaic Quality formatters.

### Empirical quality improvements

The largest single quality improvement is footprint-aware gap-fill. The previous behaviour filled every NaN pixel; the current behaviour computes a per-cube validity mask (union across bands of finite pixels), derives interior holes via `scipy.ndimage.binary_fill_holes` (with a pure-numpy 4-connected flood-fill fallback) and writes a three-state mask raster through [`write_interior_fill_mask()`](src/fill_nodata.py:92): `0` = original data, `1` = interior pixel filled by Stage C, `2` = pixel outside the flight-line footprint and intentionally left as nodata. Morphological closing with `MAX_INTERIOR_GAP_PX` (default 50, exposed on both the standalone Fill NoData algorithm and the combined pipeline) unions `binary_closing(validity, iterations=N)` into the interior fill region, bridging slits and edge-touching holes up to ~`2N` pixels wide that `binary_fill_holes` alone cannot reach. The strict topological mask was compared against the morphologically closed mask on a real hyperspectral flight cube with all other parameters held equal:

| Metric    | Strict topological mask | + `MAX_INTERIOR_GAP_PX=50` | Δ                              |
|-----------|-------------------------|----------------------------|--------------------------------|
| MEAN_RMSE | 0.07097884              | 0.00387872                 | −0.06710012 (≈ ×18 lower)      |
| MEAN_MAE  | 0.01861339              | 0.00060489                 | −0.01800850 (≈ ×30 lower)      |
| MEAN_PSNR | 28.21847672 dB          | 51.41162463 dB             | +23.19 dB                      |
| MEAN_SSIM | 0.93811815              | 0.99524193                 | +0.0571                        |

Worst-band diagnostics on the same run after the improvement (with `MAX_INTERIOR_GAP_PX=50`) show MEAN_RMSE `0.00391`, MEAN_PSNR `51.75 dB`, MEAN_SSIM `0.9956`, whole-cube SAM `2.41e-4 rad` (SAM_DEG `0.0138°`); the WORST bands for RMSE / PSNR / SSIM differ (38 / 202 / 138), confirming at least three distinct failure modes (steep-gradient bright band, low-dynamic-range SWIR / water-absorption band, structurally seam-affected band) rather than a single universally degraded channel.

Performance work was concentrated on the mosaic and gap-fill stages. The mosaic merge loop was inverted so the chunk loop is outer and the band loop inner; each chunk opens its sources exactly once and iterates `rasterio.merge.merge(..., indexes=[b])`. Total open/close count drops from `band_count × n_chunks × chunk_size` to `n_chunks × chunk_size`, a `band_count`-fold reduction that is materially significant on hyperspectral cubes. The v3 GDAL gap-fill backend [`fill_nodata_file_gdal()`](src/fill_nodata.py:992) wraps `gdal.FillNodata` (native C, ~10–100× faster than the pure-Python v2 IDW quadrant sweeps) and falls back to v2 on any non-cancellation exception; it is now the production default in [`GAP_FILL_METHODS`](src/methods.py:134). Stage C also supports a tiled mode (`tile_size > 0`) that walks each band as inner cores with a halo of `max_search_dist + smoothing_iterations` pixels (observationally identical to whole-band processing), and an `n_workers > 1` mode that submits each band to a `ThreadPoolExecutor` via [`_fill_band_worker()`](src/fill_nodata.py:1) (the parent serialises GDAL writes via `as_completed`). The executor was changed from `ProcessPoolExecutor` to `ThreadPoolExecutor` to avoid Windows `spawn` re-importing QGIS in worker processes.

### Spectral-fidelity policy and the curation of mosaic methods

Two visual-quality mosaic methods, `v4_feather` (distance-transform feathered blending) and `v5_histmatch_feather` (linear moment histogram matching against the first input followed by feathered blending), were implemented and registered for a brief period. They were subsequently unregistered and deleted to align the codebase with the explicit policy in *Project policy — data correctness over visual appearance*: any operation that mixes, rescales or interpolates per-pixel spectral values across frames is incompatible with the spectral-fidelity guarantee and is therefore prohibited from registration as a production method. The `MAX_FEATHER_PX` parameter was removed from [`MosaicAlgorithm`](mosaic_algorithm.py:1) and [`HyperspectralPipelineAlgorithm`](hyperspectral_algorithm.py:1) along with the conditional dispatch in [`run_pipeline()`](src/pipeline.py:166); the helper functions `_feather_weights`, `mosaic_frames_feather` and `mosaic_frames_histmatch_feather` were initially left as unreachable dead code and have since been deleted from [`src/mosaic.py`](src/mosaic.py:1). Saved Model Builder graphs that explicitly set `MAX_FEATHER_PX` or selected mosaic indices `1` / `2` from the now-defunct ordering silently ignore the unknown parameter or fall back to index `0` — both are acceptable degradations and no `name()` / `displayName()` / `groupId()` was changed.

The three currently registered mosaic methods are all spectrally faithful. `v1_first_write_wins` ([`mosaic_frames()`](src/mosaic.py:196)) preserves the historical first-pixel-wins behaviour. `v2_best_pixel` ([`mosaic_frames_best_pixel()`](src/mosaic.py:403)), recommended for visual quality, picks the source frame with the maximum distance-to-edge per pixel via `scipy.ndimage.distance_transform_edt` and copies the entire spectrum of that frame into the output, so no spectral mixing occurs; ties are resolved by input order and provenance is optionally written to `<output>.sources.tif`. `v3_vrt` ([`mosaic_frames_vrt()`](src/mosaic.py:683)) builds an in-memory VRT via `gdal.BuildVRT(resolution="highest", resampleAlg=Resampling.nearest)` and translates it to GeoTIFF with the same creation options as the other methods; on non-overlapping inputs it is byte-for-byte identical to v1. The gap-fill default was reordered so `v3_gdal_fillnodata` precedes `v2_idw_quadrants` — the C backend is the same algorithm family but materially faster and is preferred over the pure-Python alternative.

### Hyperspectral metadata and raw airborne georeferencing

A dedicated metadata layer was added to support raw hyperspectral cubes. [`src/envi_io.py`](src/envi_io.py:1) is a thin lazy wrapper over `spectral.io.envi.read_envi_header`; it exposes a frozen [`EnviHeader`](src/envi_io.py:29) dataclass (`samples`, `lines`, `bands`, `interleave`, `data_type`, `byte_order`, `wavelengths`, `fwhm`, `bbl`, `band_names`, `wavelength_units`) and a single [`read_envi_header()`](src/envi_io.py:45) call. [`src/models.py`](src/models.py:1) provides passive path-bundling: [`FlightLineMeta`](src/models.py:15) plus [`discover_flight_line()`](src/models.py:32), which locates a sibling `.hdr` (required) and `.times` / `.lcf` (optional). `RasterCubeMeta` and `ProcessingProfile` were considered and deferred as having no consumer.

Pushbroom raw-cube georeferencing lives in [`src/airborne_georef.py`](src/airborne_georef.py:1). Sidecar parsers cover `.lcf` (`time, roll, pitch, yaw` in radians, `lon, lat` in degrees, `alt` in metres) and `.times`; the two files use different absolute epochs but cover the same flight segment and are aligned by **relative** time (each file's first timestamp subtracted), with `np.unwrap(yaw)` handling angular wrap-around. Pose interpolation is per-image-frame. The pushbroom projection model treats `fov_deg` as a required parameter (hyperspectral camera lenses differ; there is no safe default); body-frame rays `[0, sin(angle), -cos(angle)]` are rotated into ENU through the composed `R = Rz(yaw) @ Ry(pitch) @ Rx(roll)` (the rotation matrix is built once by a shared module-level [`_build_rotation_matrix()`](src/airborne_georef.py:1) helper and reused for both the body and the boresight rotations) and intersected with the flat ground plane `z = ground_alt` (or with terrain in the DEM-aware path). Rays not pointing downward (`dz >= -1e-6`) or with non-positive scale are marked invalid. ENU→geodetic conversion uses [`pymap3d.enu2geodetic()`](src/airborne_georef.py:1) with the documented return order `(lat, lon, alt)`.

DEM-aware geolocation [`dem_ground_grid()`](src/airborne_georef.py:920) iteratively intersects each pushbroom ray with terrain, starting from a `fallback_ground_alt` and stopping by tolerance or max iterations; nearest-neighbour DEM sampling via rasterio is used, the DEM CRS is handled directly when it is `EPSG:4326` and through `pyproj.Transformer(always_xy=True)` otherwise, missing DEM paths fail with a clear `FileNotFoundError`, and nodata / non-finite DEM samples are treated as invalid rather than as accepted fallback terrain. Boresight angles (`boresight_roll_deg`, `boresight_pitch_deg`, `boresight_yaw_deg`, all degrees, Z-Y-X intrinsic Euler, right-handed) and `time_offset_s` (seconds, added to the image-frame timestamp before pose lookup) were added as optional kwargs on [`write_flat_geotiff()`](src/airborne_georef.py:704) and as advanced QGIS parameters; defaults are zero and produce byte-identical output to the un-boresighted path. The GeoTIFF writer uses rasterio geolocation arrays (`src_geoloc_array=(grid.lon, grid.lat)`) with `Resampling.nearest` to preserve spectral safety; the destination nodata is always set in the profile (NaN for float dtypes, `0` for integer dtypes) and initialised through `init_dest_nodata=True` so georeferenced outputs no longer carry opaque black borders. `src_crs=CRS.from_string("EPSG:4326")` is passed explicitly because rasterio ≥ 1.5 rejects the raw string in geolocation-array reprojection. An optional vector footprint is emitted by [`extract_footprint_polygon()`](src/airborne_georef.py:488) / [`write_footprint_vector()`](src/airborne_georef.py:559) (GeoJSON / GPKG / SHP, format inferred from extension) and wired into the QGIS algorithm via `OUTPUT_FOOTPRINT`. The raw stage is integrated into QGIS as [`AirborneGeorefAlgorithm`](airborne_georef_algorithm.py:39) (`gapsfiller:airborne_georef`) and verified end-to-end on a Pika L 28-band capture in [`example/`](example/); flat-earth output reproduces the expected grid shape and bounds, while the DEM-aware path is implemented but not yet exercised end-to-end on a capture with a real DEM. Orientation calibration (sign conventions on roll / pitch / yaw) still requires visual validation in QGIS against a basemap before scientific use.

### Repository reorganization — pure-Python core in `src/`, QGIS wrappers at the root

The codebase was reorganized so that layering is explicit at the file-system level. The nine pure-Python modules — [`src/airborne_georef.py`](src/airborne_georef.py:1), [`src/envi_io.py`](src/envi_io.py:1), [`src/fill_nodata.py`](src/fill_nodata.py:1), [`src/frame_filter.py`](src/frame_filter.py:1), [`src/methods.py`](src/methods.py:1), [`src/models.py`](src/models.py:1), [`src/mosaic.py`](src/mosaic.py:1), [`src/mosaic_quality.py`](src/mosaic_quality.py:1), [`src/pipeline.py`](src/pipeline.py:1) — were collected into a package with an empty [`src/__init__.py`](src/__init__.py:1) and no Qt / QGIS imports, while QGIS-facing files (the plugin entry [`__init__.py`](__init__.py:1), the plugin class [`gaps_filler.py`](gaps_filler.py:1), the Processing provider [`gaps_filler_provider.py`](gaps_filler_provider.py:1), the six `*_algorithm.py` wrappers, [`canvas_styling.py`](canvas_styling.py:1), [`qgis_helpers.py`](qgis_helpers.py:1), [`metadata.txt`](metadata.txt:1), [`pb_tool.cfg`](pb_tool.cfg:1)) remain at the workspace root. Cross-module imports inside `src/` use relative form (`from .models import …`); root QGIS files import core logic via `from .src import …` or `from .src.<module> import …`. [`pb_tool.cfg`](pb_tool.cfg:1) lists `src` in `extra_dirs` so the package ships to QGIS as a unit, and the nine moved files were removed from `python_files`. No logic changed in the move; the second half of the longstanding `core/` + `qgis/` split — moving the wrapper layer into a sibling `qgis/` package — remains deferred (see *Remaining open questions and backlog* above).

In parallel with the reorganization, a small QGIS-side cleanup landed: a shared [`qgis_helpers.py`](qgis_helpers.py:1) module hosts `handle_processing_exception(exc)`, consolidating the repeated `try / except → QgsProcessingException` pattern across wrappers; the inline post-processor blocks in the Mosaic, Fill NoData and Airborne Georef algorithms were replaced by `attach_rgb_post_processor_if_needed` in [`canvas_styling.py`](canvas_styling.py:1); and the magic number `280` (historical Pika L band count) was replaced by a named `DEFAULT_PIKA_L_BANDS` constant in [`src/models.py`](src/models.py:1), now used by [`airborne_georef_algorithm.py`](airborne_georef_algorithm.py:1). A code-quality sweep across the core modules hoisted `from osgeo import gdal` to module top in [`src/fill_nodata.py`](src/fill_nodata.py:1), extracted [`_safe_delete_raster()`](src/fill_nodata.py:1) and the shared [`_reproject_if_needed()`](src/mosaic.py:123) helper used by [`mosaic_frames()`](src/mosaic.py:196), [`mosaic_frames_best_pixel()`](src/mosaic.py:403) and [`mosaic_frames_vrt()`](src/mosaic.py:683), made the per-band saturation check in [`src/frame_filter.py`](src/frame_filter.py:1) dtype-aware via `np.issubdtype(...)` so it no longer raises on non-int non-float arrays, wrapped OGR resource creation in the footprint writer in `try / finally`, replaced a bare `except Exception` in [`_load_fillmask()`](src/mosaic_quality.py:1) with the specific `(OSError, RuntimeError)` pair, and added a per-source `pixel_cache` to [`mosaic_frames_best_pixel()`](src/mosaic.py:403) so each source is now read once per chunk rather than twice.
